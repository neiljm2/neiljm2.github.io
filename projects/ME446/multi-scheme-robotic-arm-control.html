Project Overview

  • Course & Context: Final cumulative project for my ME 446 (Robot Dynamics and Control) course.
  • Challenge: Guide a robotic arm's end effector peg a certain depth into a hole, then trace a curved path with tight edges, then apply a ~5 Newtons to an egg.

Control Architecture

The core logic governing the robotic arm is written in C (FINAL_PROJ.c) and executes in real-time at 1000 Hz. The system utilizes multiple advanced control strategies simultaneously:

  • Task Space Control (Jacobian Transpose): Instead of commanding individual joint angles directly (joint space control), the control law operates entirely in the Cartesian "World" frame (task space control). The error between the desired XYZ position and the end effector's actual position is calculated for use in a PD controller. The necessary restorative Cartesian forces are computed and then projected into individual motor joint torques using the Jacobian Transpose matrix.
  • Impedance Control & Transformations: The robot actively changes its compliance depending on the task. By rotating the World frame error into a local "Node" frame (using a Z-axis rotation matrix), the controller can assign different stiffnesses (Proportional/Derivative gains) to different local axes. For example, when tracing a tight curve, the arm can be set to be physically "soft" in the X and Y axes to easily slide along the walls, while remaining completely rigid in the Z axis to maintain height. These local Node forces are then transformed back to the World frame before applying the Jacobian Transpose.
  • Feedforward Friction Compensation: The arm implements directional Coulomb and viscous friction compensation. By evaluating the real-time angular velocity of each joint, the system applies an opposing feedforward torque to cancel out the physical drag of the motors. When velocity is near zero, a high viscous damping gain prevents jitter and stabilizes the joint.

Point Struct Instruction Set

The arm's sequence of actions is defined by an array of point structs. Each waypoint contains a specific set of instructions that configures the controller dynamically as the arm reaches it: 

typedef struct point_tag {
    float x;    // Target Cartesian X position in meters (World Frame)
    float y;    // Target Cartesian Y position in meters (World Frame)
    float z;    // Target Cartesian Z position in meters (World Frame)
    float thz;  // Rotation angle (Theta Z) to orient the "Node" stiffness frame
    float V;    // Desired travel velocity (m/s) to reach this point
    int mode;   // Impedance Mode (XYZSTIFF, ZSTIFF, XZSTIFF, XYSTIFF, LOWSTIFF)
} point;

The thz and mode parameters allow the controller to seamlessly transition between rigid tracking and soft compliance on the fly. For instance, when applying force to a delicate egg, the arm can switch to XYSTIFF mode, allowing it to gently rest against the object in the Z direction without breaking it.

Trajectory Generation

To move between the waypoints defined in the struct array smoothly, the controller employs a linear trajectory generator. When the arm is commanded to move from its current position to the next target point, it doesn't instantly jump the reference command to the final destination (which would cause a massive error spike and violently jerk the arm).

Instead, the system calculates the 3D Cartesian distance (distAB) between the start point and the end point. Using the desired velocity (V) specified in the target's struct, it determines the total travel time required (t_total = distAB / V).

The exact trajectory equations executed in real-time to compute the instantaneous target position (\( x_D \), \( y_D \), \( z_D \)) are:

$$ x_D = \Delta x \frac{t - t_{start}}{t_{total}} + x_a $$ $$ y_D = \Delta y \frac{t - t_{start}}{t_{total}} + y_a $$ $$ z_D = \Delta z \frac{t - t_{start}}{t_{total}} + z_a $$

At every 1 ms control loop iteration, the elapsed time (\( t - t_{start} \)) is checked against \( t_{total} \), and this linear interpolation generates the next intermediate target position. This ensures the end effector traces a perfectly straight line through 3D space at a constant, smooth velocity between every waypoint, completely eliminating step overshoots and jerky motor behavior.
